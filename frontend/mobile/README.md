# Atrium mobile (Flutter)

The Aurelius advisor app for phones: Android and iOS from one Dart codebase, and it also runs in Chrome.

Like the web app, it talks to **one** service, the Conductor. It never calls an agent directly.

```
Phone / emulator / Chrome
   │  https or http (dev) + advisor JWT
   ▼
Conductor :8000 ──► Liaison, Analyst, Notary, Actuary, Pulse, Scribe, Herald, Librarian, Sentinel
```

## Screens

| Tab / screen | What it shows | Conductor endpoint |
|---|---|---|
| Sign in | Dev password, then a JWT kept in the phone's keystore | `POST /v1/auth/login` |
| Households | The advisor's households | `GET /v1/clients` |
| Household | Header, agent strip, Needs you, Portfolio, Retirement odds (tap ages), Market, Meetings | `GET /v1/clients/{id}/overview` + `POST /v1/skills/actuary/project_retirement` |
| Write to them | Herald drafts, you edit, Sentinel re-checks, the approval is logged to the CRM | `POST /v1/skills/herald/draft_email`, `POST /v1/drafts/approve` |
| News | Live market events from Pulse (Go), no refresh needed, badge for unseen | `GET /v1/stream` (SSE) |
| Ask | Free-form questions; from a household, about that household | `POST /v1/chat` |

## Project layout

```
frontend/mobile/
├─ pubspec.yaml              dependencies (http, flutter_secure_storage)
├─ analysis_options.yaml     lint rules for `flutter analyze`
├─ lib/
│  ├─ main.dart              starts the app: session restore, theme, sign-in or home
│  ├─ config.dart            where the Conductor is (emulator vs Chrome vs real phone)
│  ├─ api/
│  │  ├─ api_client.dart     the ONLY network code: token, 401 → sign-out, trace IDs
│  │  ├─ models.dart         typed classes for every Conductor answer
│  │  └─ sse.dart            parses the live news stream
│  ├─ state/
│  │  ├─ session.dart        sign-in state (ChangeNotifier) + secure token storage
│  │  ├─ app_scope.dart      hands the session to every screen (InheritedWidget)
│  │  └─ news_controller.dart live news with reconnect and backoff
│  ├─ logic/needs.dart       "Needs you" rules (pure Dart, unit-tested)
│  ├─ ui/                    theme (same palette as the web), formatting, shared widgets
│  └─ screens/               sign_in, home_shell (tabs), households, household, email, news, ask
├─ test/
│  ├─ unit_test.dart         formatting, SSE, JWT, models, needs, API client, session
│  ├─ widget_test.dart       real screens on a phone-sized canvas, fake Conductor
│  ├─ helpers.dart           the fake Conductor (http MockClient)
│  └─ fixtures/              REAL recorded agent outputs (Patel household)
└─ android_overrides/        debug-only network settings, copied into android/ once
```

`android/`, `ios/` and `web/` are generated by `flutter create` on your machine (see TESTING.md). They're standard and don't need hand-editing, apart from the one debug override.

## Flutter concepts this project shows

| Concept | Where |
|---|---|
| Stateless vs Stateful widgets, `setState` | every screen |
| `FutureBuilder` (load once in `didChangeDependencies`, never in `build`) | households, household, retirement |
| `ChangeNotifier` + `ListenableBuilder` (simple state management) | `Session`, `NewsController` |
| `InheritedWidget` (what Provider/Riverpod are built on) | `AppScope` |
| Streams, `async*`, `await for` | `sse.dart`, `marketEvents()` |
| Navigation: tabs (`NavigationBar` + `IndexedStack`) and pushed pages | `home_shell.dart` |
| Dart 3: records, switch expressions, null safety, constructor tear-offs | `news_screen.dart`, `widgets.dart`, `models.dart` |
| Dependency injection for tests (`http.Client`, `TokenStore`) | `api_client.dart`, `session.dart` |
| Unit and widget tests with a fake backend | `test/` |

## Security choices

- **One door.** The phone only knows the Conductor. Agent URLs and the SERVICE_TOKEN are never in the app.
- **Token in the keystore.** `flutter_secure_storage` uses the Android Keystore and the iOS Keychain, never plain preferences. The app signs out when the token expires, on any 401, and closes any open screens when it does.
- **HTTPS by default.** Android blocks `http://`. Only debug builds allow it, and only to `10.0.2.2`, `127.0.0.1` and `localhost` (`android_overrides/.../network_security_config.xml`). Release builds need HTTPS.
- **Token never in a URL.** The live news stream sends it as a header.
- **Human in the loop.** The app won't approve an email while `[placeholders]` remain. Sentinel re-checks every approval, and if it changes the text you see the revised version. Aurelius never sends email.
- **Traceable errors.** Errors show the `X-Trace-Id`, so the same request can be found in every agent's log.
- **Defensive parsing.** A missing field becomes an empty value, not a crash, and one agent failing shows "didn't answer" while the rest of the file still works.
